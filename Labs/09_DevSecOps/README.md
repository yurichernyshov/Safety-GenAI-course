# Общие сведения

## Безопасность Jenkins
Jenkins является критическим звеном в инфраструктуре, так как часто имеет доступ к исходному коду, секретам (пароли, ключи SSH) и продакшн-средам.
Основные меры защиты:
- Аутентификация: Отключение анонимного доступа, использование надежных паролей или интеграция с LDAP/AD.
- Авторизация: Использование матричной системы прав (Matrix-based security) для разделения прав между администраторами, разработчиками и читателями.
- Сеть: Ограничение доступа к порту Jenkins (8080) только с доверенных IP или через VPN/Reverse Proxy (Nginx).
- Плагины: Регулярное обновление плагинов для устранения уязвимостей.
- Secrets Management: Хранение чувствительных данных в Credentials Store, а не в скриптах.

## Системы мониторинга (Prometheus + Grafana)
- Prometheus: Система сбора и хранения метрик (Time Series Database). Опрос целевых систем по HTTP.
- Node Exporter: Экспортер метрик операционной системы (CPU, RAM, Disk).
- Grafana: Система визуализации. Строит графики на основе данных из Prometheus.
- Jenkins Prometheus Plugin: Плагин, открывающий эндпоинт /prometheus со статистикой сборок, очередей и статусом узлов.


## Цели
- Изучить принципы безопасной настройки сервера автоматизации Jenkins.
- Настроить систему контроля доступа (RBAC) в Jenkins.
- Развернуть стек мониторинга (Prometheus + Grafana + Node Exporter).
- Настроить сбор метрик с Jenkins и инфраструктуры.
- Визуализировать данные о состоянии CI/CD пайплайнов и сервера в Grafana.

## Требования к окружению
- ОС: Ubuntu 20.04/22.04 (или любая другая с поддержкой Docker).
- ПО: Docker, Docker Compose.
- Доступ: Root-права или пользователь в группе docker.
- Порты: 8080 (Jenkins), 3000 (Grafana), 9090 (Prometheus), 9100 (Node Exporter).

# Ход работы

Этап 1: развертывание инфраструктуры
Установить docker
https://docs.docker.com/engine/install/ubuntu/

Создать рабочую директорию
Создать dockerfile
Создать файл конфигурации prometeus.yml
Запуск
```bash
$ docker-compose up -d
$ docker-compose ps
```

Этап 2: безопасная настройка Jenkins
1.	Откройте браузер и перейдите по адресу http://<IP-сервера>:8080.
2.	Войдите под учетной записью:
a.	Login: admin
b.	Password: admin123
3.	Смена пароля (Обязательно):
a.	Нажмите на имя пользователя (справа вверху) -> Configure.
b.	Введите новый надежный пароль. Сохраните.
4.	Настройка прав доступа (Matrix-based security):
a.	Перейдите: Manage Jenkins -> Security -> Authorization.
b.	Выберите Matrix-based security.
c.	В поле "User/group to add" введите admin и нажмите Add.
d.	Выдайте пользователю admin все права (галочка в заголовке столбца).
e.	Добавьте пользователя developer (создадим его позже) и выдайте ему права только на Read (Overall) и Build (Job).
f.	Важно: Убедитесь, что у группы anonymous нет прав (или только Read, если требуется публичный доступ, но для безопасности лучше убрать все).
g.	Нажмите Save.
5.	Создание пользователя developer:
a.	Manage Jenkins -> Security -> Users -> Create User.
b.	Username: developer, Password: dev123.
6.	Проверка безопасности:
a.	Выйдите из системы (Logout).
b.	Попробуйте зайти без авторизации (должно перенаправлять на логин).
c.	Зайдите под developer. Попробуйте зайти в "Manage Jenkins" (доступ должен быть запрещен).
d.	Зайдите под admin. Доступ должен быть полным.

Этап 3: Настройка сбора метрик Jenkins
1.	Зайдите в Jenkins под admin.
2.	Перейдите: Manage Jenkins -> Plugins -> Available plugins.
3.	Найдите и установите плагин Prometheus metrics. (После установки может потребоваться перезагрузка Jenkins).
4.	Проверьте доступность метрик:
a.	Откройте в новой вкладке: http://<IP-сервера>:8080/prometheus.
b.	Вы должны увидеть текст в формате Prometheus (метрики начинаются с default_jenkins_...).
c.	Примечание: Если вы видите ошибку 403, проверьте настройки безопасности. Метрики должны быть доступны для мониторинга. В плагине Prometheus можно настроить "Default Authentication", но для лабораторной работы убедитесь, что Prometheus в docker-compose имеет доступ к сети Jenkins.

Этап 4: Настройка Grafana
1.	Откройте браузер: http://<IP-сервера>:3000.
2.	Войдите под grafana_admin / grafana123.
3.	Добавление источника данных (Data Source):
a.	Нажмите Connections (или шестеренку) -> Data Sources -> Add data source.
b.	Выберите Prometheus.
c.	В поле Server URL введите: http://prometheus:9090 (имя сервиса из docker-compose).
d.	Нажмите Save & test. Должно появиться сообщение "Data source is working".
4.	Импорт дашборда:
a.	Перейдите в Dashboards -> New -> Import.
b.	В поле "Import via grafana.com" введите ID дашборда: 9964 (Jenkins Metrics) или 1860 (Node Exporter Full).
c.	Нажмите Load.
d.	Выберите источник данных (Prometheus), который вы создали ранее.
e.	Нажмите Import.
5.	Повторите процедуру импорта для второго дашборда (чтобы видеть и метрики Jenkins, и метрики ОС).

Этап 5: Генерация нагрузки и верификация
1.	В Jenkins создайте новый Freestyle project с названием test-job.
2.	В настройках задачи добавьте шаг сборки Execute shell с командой:
```bash
echo "Running build..."
sleep 10
echo "Build complete"
```
1.	В разделе Build Triggers выберите Build periodically и укажите * * * * * (запуск каждую минуту) для теста.
2.	Сохраните задачу.
3.	Подождите 2-3 минуты.
4.	Перейдите в Grafana на дашборд Jenkins.
5.	Убедитесь, что графики (количество сборок, длительность, статус) начали обновляться.
6.	Перейдите на дашборд Node Exporter. Убедитесь, что видна нагрузка на CPU/RAM хоста.
